# Published campaign comparison

This table compares the shipped `small-run` profile, composed with the packaged campaign template, against Anthropic's [released multi-target campaign prompt](https://huggingface.co/datasets/Anthropic/claude-protein-binder-design/blob/d442eeb/prompts/prompts/multi_target_binder_design_prompt.md). The prompt release and the accompanying [technical report](https://www-cdn.anthropic.com/30bf50e22a01388bb29bf077ee3f244531594b7a.pdf) are the primary sources. The first column reports their requirements without inferring unrecorded campaign behavior. [Published targets](published-targets.md) transcribes twelve of the prompt's fourteen targets and their construct and epitope rules.

Package configuration reviewed 2026-09-09. This table describes template defaults.

The small run has two provider routes, and every verdict below holds for both. `small-run.template.json` reaches its three tools over HTTPS deployments you own and asks you for three URLs in `provider_endpoints`. `small-run-modal.template.json` runs on your own Modal account and asks you instead for a workspace, a spend ceiling, and one environment identity and image reference per adapter group. The **Generator** row is the one place they differ. The Modal route calls `claude_binder.adapters.rfdiffusion_generator` and generates with RFdiffusion, because `rfdiffusion3_generator` reaches its model over an HTTPS deployment and has no Modal binding in this package. The protocol's roster names both RFdiffusion and RFdiffusion3, so the two routes cover different arms of it.

The **Generator**, **Sequence designer**, and **Co-folding arms** rows below describe settings. For which of those arms the package can actually invoke, read [Reproduction readiness](reproduction-readiness.md), which derives the answer from shipped files.
